# Log Parser Service (Yadro Test 2026)

Микросервис на Go для парсинга логов и представления данных для анализа топологии сети.

## О сервисе

Данный микросервис предназначен для парсинга архивов, содержащих логи со специализированными типами файлов (`.db_csv` и `.sharp_an_info`), сохранения данных в реляционную базу и предоставления удобного REST API для получения топологии и статистики.

## Технологический стек

- **Язык:** Go 1.26.1 (стандартная библиотека `net/http`)
- **СУБД:** PostgreSQL
- **Драйвер БД:** `pgx/v5` (`pgxpool`)
- **Логирование:** `log/slog`
- **Контейнеризация:** Docker & Docker Compose

## Функционал

- Разархивирование `.zip` архивов и валидация содержимого
- Парсинг CSV и текстовых файлов с учётом спецификации оборудования
- Агрегация данных: узлы, порты, мета-информация
- Graceful shutdown и корректная обработка ошибок
- Структурированное логирование запросов и ошибок

## Подготовка к использованию

Приложение запускается в Docker. Для работы необходимо установить [Docker Desktop](https://www.docker.com/products/docker-desktop/).

### Шаги запуска

1. **Клонирование репозитория:**
   ```bash
   git clone https://github.com/suhrobdomoiZ/yadro-test-2026.git
   cd yadro-test-2026
   ```

2. **Подготовка данных:**  
   Создайте папку `data` в корне проекта и положите туда `.zip` архив с логами.
   ```bash
   mkdir -p data
   cp /path/to/your/logs.zip data/logs.zip
   ```

3. **Настройка переменных окружения:**  
   Создайте файл `.env` в корне проекта на основе `config/.env.example`.

4. **Запуск:**  
   Сборка и старт сервисов выполняются одной командой:
   ```bash
   docker compose up -d --build
   ```

5. При первом запуске автоматически применятся миграции, и база данных будет готова к работе.

## API

**Base URL:** `http://localhost:8080`  
Все эндпоинты принимают и отдают данные в формате **JSON**.

### 1. Загрузка и парсинг лога

Принимает путь к архиву, распаковывает его, парсит данные и сохраняет в БД.

- **Метод:** `POST`
- **Путь:** `/api/v1/parse/`

**Тело запроса:**
```json
{
  "path": "logs.zip"
}
```

> **Важно:** В поле `path` передавайте только имя файла. Папка `data/` добавится автоматически

**Пример запроса:**
```bash
curl -X POST http://localhost:8080/api/v1/parse/ \
  -H "Content-Type: application/json" \
  -d '{"path": "logs.zip"}'
```

**Ответ (200 OK):**
```json
{
  "log_id": 1
}
```

**Ошибки:**
- `400 Bad Request` — некорректный путь или архив не является `.zip`
- `404 Not Found` — файл не найден или в архиве отсутствуют требуемые файлы (`.db_csv`, `.sharp_an_info`)

---

### 2. Получение топологии

Возвращает структуру сети, сгруппированную по типам узлов (Switches, Hosts), с вложенными списками портов.

- **Метод:** `GET`
- **Путь:** `/api/v1/topology/{log_id}`

**Параметры:**
- `log_id` (int) — ID лога в системе.

**Пример запроса:**
```bash
curl http://localhost:8080/api/v1/topology/1
```

**Ответ (200 OK):**
```json
{
  "log_id": 1,
  "switches": [
    {
      "guid": "0xswitch1",
      "description": "SWITCH_1",
      "node_type": 2,
      "ports": [
        {
          "guid": "0xport1",
          "number": 1,
          "state": 4,
          "link_speed": 2048,
          "lid": 1
        }
      ]
    }
  ],
  "hosts": [
    {
      "guid": "0xhost1",
      "description": "HOST_1",
      "node_type": 1,
      "ports": []
    }
  ]
}
```

---

### 3. Детали узла

Возвращает полную информацию об узле, включая метаданные из таблицы `nodes_info`.

- **Метод:** `GET`
- **Путь:** `/api/v1/node/{node_id}`

**Параметры:**
- `node_id` (int) — ID узла.

**Пример запроса:**
```bash
curl http://localhost:8080/api/v1/node/5
```

**Ответ (200 OK):**
```json
{
  "id": 5,
  "log_id": 1,
  "guid": "0xswitch1",
  "description": "SWITCH_1",
  "node_type": 2,
  "system_image_guid": "0xswitch1",
  "base_version": 1,
  "class_version": 1,
  "info": {
    "serial_number": "SOS123",
    "product_name": "Gorilla",
    "part_number": "MMM-MAV",
    "revision": "AA"
  }
}
```

> Поле `info` может отсутствовать, если данные не были найдены в логе.

---

### 4. Получение портов узла

Возвращает список всех портов, принадлежащих конкретному узлу.

- **Метод:** `GET`
- **Путь:** `/api/v1/port/{node_id}`

**Параметры:**
- `node_id` (int) — ID узла.

**Пример запроса:**
```bash
curl http://localhost:8080/api/v1/port/5
```

**Ответ (200 OK):**
```json
[
  {
    "id": 10,
    "log_id": 1,
    "node_id": 5,
    "guid": "0xport_guid",
    "number": 1,
    "lid": 1,
    "state": 4,
    "physical_state": 5,
    "link_speed": 2048,
    "link_width": 4
  }
]
```

> Возвращает массив объектов. Если портов нет — вернётся пустой массив `[]`.

---

### 5. Мета-информация о логе

Возвращает статус обработки, дату загрузки и агрегированную статистику (количество узлов и портов).

- **Метод:** `GET`
- **Путь:** `/api/v1/log/{log_id}`

**Параметры:**
- `log_id` (int) — ID лога.

**Пример запроса:**
```bash
curl http://localhost:8080/api/v1/log/1
```

**Ответ (200 OK):**
```json
{
  "id": 1,
  "filename": "logs.zip",
  "status": "completed",
  "created_at": "2024-05-20T14:30:00Z",
  "node_count": 5,
  "port_count": 150
}
```

**Статусы обработки:**
- `processing` — в процессе обработки
- `completed` — успешно обработан
- `error` — ошибка при парсинге
